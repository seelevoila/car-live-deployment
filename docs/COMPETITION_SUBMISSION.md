# 参赛交付说明

## 1. 项目定位

本项目是面向汽车销售直播的本地智能体，包含汽车资料知识库、车型问答、GPT-SoVITS 流式播报、动态改稿和参考音频克隆。按用户要求，大模型仅预留接口，未配置时演示本地依据摘录；赛题要求的实际大模型问答需接入后再验收。

本轮最新结果见 `artifacts/implementation-2026-09-07/最终赛题验收报告.md`。数字主播仅在本地迭代，提交源码ZIP暂未重建；旧PDF、PPT和视频/云端交付不因本轮代码修复自动变为完成。

## 2. 题目要求对照

| 题目要求 | 当前实现 | 演示入口 |
| --- | --- | --- |
| PDF / Word / TXT 批量知识库 | 支持批量上传、搜索、编辑和删除，资料替换与版本记录，来源及许可维护，导入前标识脱敏 | 知识库 |
| 向量化、结构化、溯源 | SQLite持久化256维哈希向量、元数据、片段、页码和版本；哈希向量与词法混合检索，尚未引入预训练语义向量模型 | 知识库 / 问答 |
| 检索准确率 >=85%，至少 40 条样本 | 内置 40 条检索样本，最近一次 40/40，100%；最终问答样本 40/40，100% | 验证 |
| 流式音频生成播放 | 前后端按自然停顿切分；GPT-SoVITS PCM WAV 分片到达即排程 Web Audio 播放，后续 WAV 头被剥离后连续拼接 | 直播台 |
| 动态改稿 | 按自然停顿切分；保留当前短语，取消过期后续请求并刷新新稿 | 直播台“应用动态改稿” |
| 首音频 <=3 秒 | 三轮浏览器热态测试9个样本，预计首个有声帧1.68–1.90秒；未包含启动预热和物理扬声器回录，详见最终报告 | 验证 / 三轮报告 |
| 语速、音量、语调 | 滑块参数作用于新合成/排程的音频，四种播报风格可选；语调变换同时改变播放时长 | 直播台 |
| 真人音色克隆 | 上传参考音频和原文；仅裁掉首尾空白、保留内部停顿并做有限峰值保护后转换 PCM；质量不合格禁止播报 | 直播台 / 语音克隆 |
| 多套预置音色 | 沉稳、活力、亲民和系统默认音色 | 直播台 |
| 文字 + 语音问答 | RAG 证据展示、文字答案、当前音色流式播报 | 直播台 / 数字主播 |
| 数字主播增强展示 | 加载用户提供的 Live2D 胡桃模型；与直播脚本、动态改稿、RAG 问答和 GPT-SoVITS 共用会话链路，播报时驱动嘴型 | 数字主播 |
| 统计与听测 | 实际讲解时长、车型/问题/来源热点、改稿、延迟统计；真人五项听测评分与JSON导出 | 直播统计 / 音色听测 |

## 4. 现场演示顺序（3 分钟）

1. 在知识库导入一份 TXT 或 DOCX，展示车型、片段数量和版本记录。
2. 切换直播台车型，提问“续航是多少”，展示来源、相关度和回答语音。
3. 播放三句话脚本，在第一句播放时修改第三句，点击“应用动态改稿”，说明当前短语不被截断、后续内容使用新稿。
4. 试听当前克隆音色，展示参考文本、PCM 优化状态和语速/音量/语调参数。
5. 打开验证页，展示检索准确率、最终问答准确率和 TTS 首音频延迟。
6. 打开数字主播页，让胡桃播报一段汽车脚本，再检索一个车型问题并让她回答，展示模型、文字、溯源和语音四路联动。

## 5. 可复现验收

```powershell
powershell -ExecutionPolicy Bypass -File .\verify.ps1
```

脚本会执行Python测试、健康检查、检索、本地问答、后端TTS首PCM测试和音色质量检查，自测失败返回非零退出码。浏览器完整输出延迟需另跑三轮脚本，不能用后端首PCM结果代替。问答85%为项目内部自测目标，赛题只对检索规定85%。

## 6. 数据合规

- 示例资料位于 `data/sample`，正式使用前应由资料提供者核对公开来源、授权和政策有效期；实施方案见 `docs/DATA_COMPLIANCE.md`。
- 上传资料和参考音频默认保存在本机 `data/uploads`，不自动上传到第三方服务。
- 参考音频原始文件不会被覆盖；系统只生成标准化副本供 GPT-SoVITS 使用。
- 如果配置外部 OpenAI 兼容模型，只有用户主动填写 `LLM_BASE_URL` 后，检索片段才会发送到该地址；默认配置为空，使用本地抽取式问答。
- 参赛发布前应删除真实个人音频、内部优惠政策和未授权车型资料，并在演示机上重新初始化数据库。
- 当前克隆为GPT-SoVITS v2ProPlus少样本参考推理；赛题要求语音克隆，没有额外规定必须训练新模型。
- Live2D 模型来自演示机外部目录 `LIVE2D_MODEL_ROOT`，只读白名单路由不会把素材上传到第三方；正式参赛或公开发布前应确认胡桃模型的授权范围，必要时替换为已获授权的原创模型。

## 7. 尚需由参赛队补齐的材料

- 真人填写“音色听测”页面或 `docs/VOICE_EVALUATION.md` 的主观分数。建议至少3人，这是项目评测方案，不是赛题人数门槛。
- 根据实际队伍信息补充 PPT、系统设计 PDF、演示视频和答辩分工。
- 提交前重新运行 `verify.ps1`，将输出保存为标准化功能测试报告附件。
